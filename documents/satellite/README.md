# 衛星(CubeSat)受信の試験 — 設計

2026-11-05 に方針を決め、P0 を稼働させた。**期間限定の試験**であり、kikicom の本来の
目的(ADS-B の平常時基準線を雪害シーズンに向けて途切れず蓄積する)を置き換えない。

> **現状(2026-11-12): 一時停止中。** P1 の手動窓は 11/7〜11/10 の 9 回で終え、2026-11-11 19:30 に
> アンテナを垂直(14+14 cm)へ戻した。11/14 から約 2 週間はユーザーが留守のため、**ADS-B の基準線だけを
> 安定して続ける**。予約済みの窓は 0 件。P0 の `sat-plan.timer`(予定表を作るだけ、ADS-B に触れない)は
> 動かしたままにしてある。2 週間の試験期間(D2、〜11/19)は留守中に終わるので、再開するかは帰宅後に決める。
> 結果は下の「P1 の結果」、撤退基準(D2)の評価は「P1 の結果(続き)」。

## 位置づけと原則

- **ADS-B の基準線が最優先。** 衛星受信は RTL-SDR を「期限付きで借りる」だけ。既定の状態は常に
  ADS-B 稼働中で、どの失敗でも ADS-B に戻る設計にする。
- 対象はアアルト大学の Foresail-1p(437.125MHz、GMSK 9600bps、CW ビーコンあり)と
  Suomi-100(437.775MHz、GMSK 9600bps、60 秒ごとのビーコン)。AO-73(145.935MHz)は、
  437MHz 用のアンテナでは受けられないので、設定で無効にしてある。
- 受信できるかが分からないので、まず「見えるか」を確かめる。段階は、搬送波・CW ビーコンが
  ウォーターフォールで見える → GMSK のフレームがデコードできる → 受信報告を出す。
- SatNOGS 由来のデータ(録音・それから作った表)は CC BY-SA。CC0 の公開物に混ぜない(CLAUDE.md §4)。
  自前で受信・解読したデータは対象外。公開前に、衛星運営者の希望を確認する。

## 決定事項(2026-11-05)

| # | 決定 | 理由 |
|---|---|---|
| D1 | 置き場所は `scripts/sat/` と `documents/satellite/`。ADS-B 側のファイルは触らない | ハードウェアと調停の仕組みを共有しているので kikicom に同居。育てば姉妹リポジトリへ切り出す |
| D2 | 試験は 2 週間。CW ビーコンの検出に失敗したら、アンテナを戻して基準線を再開する | 損失を、2 週間分の基準線の質に限定する |
| D3 | ADS-B の停止は、合計で 1 日 45 分まで。窓どうしの間隔は 5 分以上 | 基準線への影響を抑える(P0 の予定では 48 時間で約 16 分) |
| D4 | 方式は「貸し出し」。窓の間だけ `adsb-research` を止め、終了時に必ず起動し直す | 見張り役のタイマーで、スケジューラが壊れても ADS-B は戻る |
| D5 | パス予測は RPi で行う | slate が止まっていても、予定と実行が RPi 単独で動く |
| D6 | 窓の記録を、ADS-B の欠測として基準線の計算から除外する | 窓の間の受信ゼロを、受信率の低下と誤記録しない |

## 構成

```
slate(開発)          RPi(実行)
  scripts/sat/*  ──install──▶  /usr/local/lib/kikicom/sat-plan.py
                              ├ sat-plan.timer(6 時間ごと)→ ~/sat/schedule.json
                              └ (P2)sat-scheduler → 窓で ADS-B を一時停止 → 受信 → 再開
  ◀── rsync ──  ~/sat/ (予定・窓の記録・パスごとの結果)
```

- 実際のユニットの関係(2026-11-05 確認): `adsb-logger` は `BindsTo=` と `WantedBy=` で
  `adsb-research` に結び付いている。research を止めれば logger も止まり、research を起動すれば
  logger も起動する。systemd は 257 で、`OnSuccess=`/`OnFailure=` が使える。

### P0 の運用

```bash
KIKICOM_RPI_HOST=<RPi の ssh 名> ./scripts/install-sat-service.sh install    # 導入・更新
KIKICOM_RPI_HOST=<RPi の ssh 名> ./scripts/install-sat-service.sh status     # 予定の確認
KIKICOM_RPI_HOST=<RPi の ssh 名> ./scripts/install-sat-service.sh uninstall  # ユニットとスクリプトを削除
```

- 観測点の正確な位置は、RPi の `~/sat/location.json`(権限 600)にだけ置く。リポジトリには入れない。
- `scripts/sat/config.json` が設定の正本。インストールで RPi の `~/sat/config.json` に上書きされる。
  - `mask`: 方位ごとの最低仰角(`方位下限-方位上限:最低仰角`)。**90〜200° 以外は仮定**(下記)。
  - `min_max_el` / `min_usable_s` / `min_usable_el`: 選ぶパスの条件。
  - `window_pad_s`: 開口に入る前後の余裕(30 秒)。
  - `daily_cap_min` / `min_gap_min`: ADS-B の停止の予算(D3)。
- 出力は `~/sat/schedule.json`(UTC)と `schedule.tsv`(JST の要約)、`plan-history.jsonl`。

### P1(手動 1 回)の運用

```bash
export KIKICOM_RPI_HOST=<RPi の ssh 名>
./scripts/sat/arm-window.sh arm SUOMI-100 437.775 "2026-11-07 09:13:40" 285 40.2   # 待機をセット
./scripts/sat/arm-window.sh status                                               # 確認
./scripts/sat/arm-window.sh disarm                                               # 取り消し
```

- `arm` は、RPi に `sat-window.sh` と `iq-analyze.py` を置き、systemd の一時タイマー 2 本を作る。
  `kikicom-sat-window-*` が開始時刻に `sat-window.sh` を動かし(`adsb-research` を止めて `rtl_sdr` で IQ を録り、
  終了時に必ず起動し直す)、`kikicom-sat-guard-*` が終了の 90 秒後に、何があっても `adsb-research` を起動する(D4)。
- 出力は RPi の `~/sat/iq/<名前>-<UTC 時刻>.u8`(rtl_sdr の 8 ビット IQ)と `.json`。ADS-B が止まっていた時刻は
  `~/sat/windows.jsonl` に残る(D6: 基準線の計算から除外する)。
- 録音のあとの解析は RPi で行う(ADS-B に影響しない。`nice` を付ける)。

```bash
~/kikicom-sat/mamba/envs/sat/bin/python /usr/local/lib/kikicom/iq-analyze.py ~/sat/iq/<名前>.u8 --norad 43804
MAMBA_ROOT_PREFIX=~/satnogs-test/mamba ~/satnogs-test/bin/micromamba run -n gr \
  gr_satellites "Suomi 100" --rawfile ~/sat/iq/<名前>.dc.cf32 --iq --samp_rate 250000
```

`iq-analyze.py` は、TLE から予測したドップラー(接近中は受信周波数が高く、遠ざかると低い)を IQ から取り除いた
`.dc.cf32` を作る。あわせて、予測した周波数の 12 kHz 帯域の電力を、両側 15〜40 kHz の参照帯域と 100 ms ごとに比べて、
短いバーストの有無を表にする(ビーコンは約 60 秒周期なので、間隔が揃っているかが決め手)。

**パイプラインの検証(2026-11-06、合成データ)。** SatNOGS の Suomi-100 の録音(FM 復調後の音声)を、実際のパスの
ドップラーに合わせた搬送波に FM 変調し直し、雑音と 8 ビット量子化を加えて、`rtl_sdr` と同じ形式の IQ を作った
(`scripts/sat/make-test-iq.py`)。この IQ で、ドップラー補正・形式・時刻合わせを通して、gr-satellites が
パケットをデコードできることを確認した。

| 検証 | 結果 |
|---|---|
| ドップラーの符号 | 接近中は +5.4 kHz から、遠ざかると -8.4 kHz。補正後の平均周波数は 0 Hz 付近(±数 Hz) |
| デコード(12 kHz 帯域の SNR) | 30 dB で 4/4 パケット、24 dB で 3/4、20 dB で 1/4、16 dB 以下は 0 |
| バースト検出(0.15 秒を 30 秒おき) | SNR 0 dB で全バーストを予定時刻に 13〜16σ、-6 dB でも多くが 4〜5σ |

合成なので、デコードの SNR の下限は目安にすぎない(再変調は本物の GMSK より劣る)。ただし、**デコードにはかなり高い
SNR が要り、1 本のホイップでの見積もり(0〜5 dB)では届かない。「見える」(バースト検出)の方がずっと低い SNR で
成立する**という関係は動かない。1 回目の目標は、デコードではなく「見える」を確かめること。

### 検出器の改良(2026-11-08)

SatNOGS の公開音声(CC BY-SA。リポジトリ外)を 2 衛星で各 36 本解析し、ビーコンのタイミングを実測した。
詳細は `miso/aalto-sats.md` の `/traces/2026-11-08-satnogs-sync-scan`。

| | Suomi 100 | Foresail-1p |
|---|---|---|
| ビーコンの間隔 | 59.999 s(標準偏差 0.005 s) | 平均 59.2 s(標準偏差 0.9 s、57.2〜60.4 s) |
| 1 回のビーコン | 1 フレーム | 3〜4 フレームの塊(約 0.4〜1.3 s) |

この実測から、`iq-analyze.py` に**周期畳み込みの探索**を足した(`--period 60`、`--jitter`、`--windows`)。ビーコンの長さに合わせた
窓(0.1/0.5/1.0 s)で電力比を作り、60 秒おきに繰り返す位相があるかを、全位相に対する有意度で出す。使い分け:

- Suomi 100: `--jitter 0.1 --windows 0.1,0.5`(間隔が極めて正確)
- Foresail-1p: `--jitter 3 --windows 0.5,1.0`(間隔が 1 秒ほどゆらぐ。塊が 0.4 秒以上ある)

**合成 IQ での比較**(2026-11-08。SatNOGS の音声を、実際のドップラーに合わせて再変調。300 s に 5 回のバースト。SNR は 12 kHz 帯):

| バースト | SNR | 旧(100 ms を 4σ) | 新(周期畳み込みの最良の窓) |
|---|---|---|---|
| 0.5 s ×60 s(Foresail 型) | −6 dB | 検出(5 回) | 28.8σ(0.5 s) |
| 同上 | **−9 dB** | **検出なし** | **10.7σ(0.5 s)** |
| 同上 | −12 dB | なし | 2.2σ(検出できず) |
| 0.15 s ×60 s(Suomi 型) | −6 dB | 検出(5 回) | 8.2σ(0.1 s) |
| 同上 | −9 dB | 1 回(誤検出と区別できず) | 3.1σ(検出できず) |
| 雑音のみ | — | 1 フレーム | 2.3〜3.0σ |

- 判定の目安: **5σ 未満は雑音の範囲、5σ 以上で候補**(対照は 1 回だけで、位相 600 個の最良が 3σ 前後。今後、対照を増やす)。
- **改善の大きさ**: Foresail 型で約 3 dB(−6 → −9 dB)、Suomi 型で 1〜2 dB 程度。**感度の壁を破るほどではない。**
  2026-11-07 の 2 回の窓で何も見えなかった(最大 3.7σ)のは、SNR が −9 dB よりかなり低かったことを意味する。
  残りの差は、アンテナ・LNA・ゲインなど受信側で埋める。
- 合成の限界: 変調の中身は SatNOGS の音声(雑音を含む)で、本物の GMSK の塊ではない。

**デコードの数え方(落とし穴)。** gr-satellites の `Suomi 100` はテレメトリを解釈して「-> Packet from」と出すが、
`FORESAIL-1P` は解釈せず、**「VERBOSE PDU DEBUG PRINT」の 16 進ダンプ**(先頭に `OH2F1S`)で出す。Foresail-1p の
成否は `grep -c '^pdu length'` で数える(「Packet from」を数えると、デコードできていても 0 件になる)。

**SatNOGS の音声 72 本の再デコード(2026-11-08)。** Suomi 100 は SatNOGS 側と同等(26/26 本)。Foresail-1p は、
ファイル単位では 13 → 15 本とあまり増えないが、**フレーム数は 27 → 205 と約 7.6 倍**。母集団では復調できる通過の割合が
約 10% から 25% 前後になる見込み(標本が小さい)。詳細は `miso/aalto-sats.md` の `/traces/2026-11-08-satnogs-redecode`。

### Foresail-1p のフレームの復号(2026-11-08)

`scripts/sat/fs1p-decode.py`(標準ライブラリのみ)が、gr-satellites の `FORESAIL-1P` のログ(16 進ダンプ)を
Skylink → PUS → ハウスキーピングまで復号する。SatNOGS 音声 72 本の再デコードで得た 205 フレームを通すと、
**ハウスキーピング 75 件(OBC 22・EPS 16・UHF 19・ADCS 18)を全て復号**でき、エラーは 0 件だった。

```bash
python3 -I scripts/sat/fs1p-decode.py ログ.log [...]    # --json で 1 行 1 JSON
```

- **バイト順は SGICD に書かれていない。** Skylink の seq・PUS ヘッダ・ハウスキーピング先頭の UNIX 時刻・ファイル転送の
  block index は**ビッグエンディアン**、ハウスキーピング本体は**リトルエンディアン**。根拠は物理的な整合:
  稼働時間がビーコンごとに +60 s、ADCS の位置ベクトルから高度 約 512 km・速度 約 7.6 km/s、バッテリー 約 8.0〜8.1 V
  (公称 6.5〜8.2 V)、降圧回路 約 3.7 V。
- **SGICD と実機の食い違い:** 実機では **UHF が TM(3,4)、ADCS が TM(3,5)**。SGICD は逆に書いている。本体の長さ
  (UHF 56 B、ADCS 79 B)と中身の両方から、実機側を採った。
- PUS の length は「サービス型 3 バイト + 本体」で、フレーム末尾の 4 バイト(認証コードと見られる。鍵が無く検証不能)を含まない。
  ハウスキーピング本体は、先頭の時刻 4 B + SGICD の表(OBC 38 B など)。
- UHF の RSSI の 3 項目は、SGICD の較正式(値 − 111 dBm)を当てると符号が合わない値が出る。生値のまま出している(未確定)。
- **科学ペイロード(ファイル転送)は復号できない。** `/r/6a19ebd6.lz4`(1,443,180 B、9,020 ブロック)と
  `/r/6a9fdb91.lz4`(2,039,810 B、12,749 ブロック)の開始報告は読めたが、手元のブロックは前者の連続 32 個
  (6048〜6080、0.35%)だけ。LZ4 は先頭から展開する必要があり、ファイルの中身(どの観測機器か)も SGICD に無い。
  全体の復元には、複数の通過・局にまたがるブロックの収集が要る。
- ハウスキーピングの値は SatNOGS の録音由来(CC BY-SA)。CC0 の公開物に混ぜない(CLAUDE.md §4)。

### P1 の結果(2026-11-07〜08、窓際のダイポール 14+14 cm、ゲイン 48 dB)

| 窓(JST) | 衛星 | 周期畳み込みの最大 | gr-satellites |
|---|---|---|---|
| 11/7 09:13、21:31 | Suomi 100、Foresail-1p | 最大 3.7σ(雑音の範囲) | 0 |
| 11/8 10:36 | Foresail-1p | 最大 3.9σ | 0 |
| 11/8 20:51(水平、292 s) | Suomi 100 | 4.1σ(0.1 s)。100 ms 単発の +6.0σ(20:51:25)は位相が合うが、続く周期は +1.0〜+1.3σ で繰り返さない | 0 |
| 11/8 21:13(水平、270 s) | Foresail-1p | **6.0σ(0.5 s)**、3.3σ(1 s)。周期ごとの山は +6.5 / +1.4 / +3.8 / +3.8σ(間隔は約 62・59・54 s) | 0 |

- **11/8 21:13 の Foresail が、これまでで最も「ビーコンかもしれない」窓。** 5σ 以上を候補とする目安(上記)を、初めて超えた。
  ただし、(1) 山の間隔が 59.2 s ±3 s の範囲で揃っていない、(2) 対照(雑音のみ)の数が少ない、(3) 4 回中 1 回は +1.4σ、
  なので、**衛星の信号とは断定できない**。復号は 0 フレーム。
  (**2026-11-09 の追記:** シミュレーションで、0.5 s・+1 dB の単発の突発 1 回だけでも 71% の試行で 5.9σ を超えると
  分かった。この σ は「繰り返し」の証拠にならない。下の「P1 の結果(続き)」を参照)
- **復号までの差(合成較正による目安)。** 0.5 s の窓の 6σ は、合成の表(−9 dB で 10.7σ、−12 dB で 2.2σ)を対数補間すると
  **12 kHz 帯の SNR で −10〜−11 dB 程度**。デコードは、合成では 16 dB 以下で 0 件、20 dB で 1/4。本物の GMSK 9k6 は
  合成(再変調)より復調しやすいはずで、8〜10 dB と見積もっても、**差は 18〜30 dB**。屋外化で得られる利得は数 dB〜10 dB
  程度と推測するが根拠は弱く、**復号まで届く見込みは低い**。一方、「見える」(周期畳み込みの σ を上げる)ことは改善を
  数値で測れる。屋外化の効果は、復号の可否ではなく **同じ条件の σ と帯域内の dB** で比べる。
- **gr-satellites の落とし穴(Foresail-1p)。** ログに「Golay decode OK」が何度も出るが、**雑音でも約 57% が通る**
  (Golay(24,12) は誤り 3 bit までを訂正するので、ランダムな 24 bit の 4096 × 2325 / 2^24 が復号できてしまう)。
  実際に 21:13 の窓で出た 20 回ほどは、誤り 3 bit・長さ 19〜242 とばらばらで、続く RS はすべて失敗。**成否は RS 後の
  `^pdu length` の数だけで見る。**
- **ベランダの見え方(計算、2026-11-08)。** 上の階に同じ張り出しのベランダがあり、手すりの外縁の真上に床板が
  あるため、**背中側(建物側、方位およそ 240°〜60°)は全仰角で見えない**。前側(60°〜240°)だけが見える。
  2026-11-09 の予測では、Foresail の窓(10:18:57〜、282 s)の **79%** が見えるが、Suomi 100 の窓(09:49:54〜、172 s)は
  **34%** しか見えない(見える区間は 09:52:00 以降で、窓の終わり 09:52:46 のあとも 09:56:30 まで続く)。
  アンテナは手すり(アルミ)の上端から 15〜20 cm 上、手すりと平行の水平(方位約 58°/238°)、外縁に置く案。
- 生の録音は、解析後に削除した(`.json` と `.log` のみ残す)。

| 11/10 10:01(232 s) | Foresail-1p | 2.2σ | 0 |

- **「約 6σ」は、単発の突発でも出る(2026-11-09、シミュレーション)。** 100 ms ごとの独立なガウス雑音(標準偏差 0.22 dB、
  2,820 フレーム)に同じ探索をかけると、雑音だけで 5.9σ 以上になるのは 1 窓あたり約 0.1%。一方、0.5 s・+1 dB の
  突発が 1 回あるだけで 71%、周期的な 4 回・+0.4 dB で 67%。**この探索は「1 つの位相に何かある」を測っており、
  「約 60 秒ごとに繰り返す」を測っていない。**
- **実データでも確かめた(11/10)。** Suomi 100 の録音で信号から +50 kHz 外した対照が、+6.4σ の単発 1 フレームだけで
  5.3σ になった。本番の 5.8σ と同じ形。
- **山の間隔は、ランダムと区別できない。** 6 個の間隔のうち、実測の送信間隔の範囲(57.2〜60.4 s)に入るのは 2 個。
  ±3 s の許容幅の中で位置がランダムでも、約 46% は入る。
- **「時間とともに弱まる」形も、信号の証拠ではない。** 11/9 の録音の対照(±30/50/70 kHz)6 か所のうち 3 か所で同じ形、
  3 か所で逆の形が出た。ドップラーの追尾が受信機の周波数特性の上を滑ることによる、基線のゆっくりした変化と見ている。
- **判定:** 予測した帯域に短い突発があった(11/8 21:14:12、11/9 10:20:25 JST)ことは支持されるが、
  **Foresail-1p・Suomi 100 の信号とは言えない**(地上の干渉を排除できない)。復号は 9 回とも 0。
  撤退基準(D2: CW ビーコンの検出に失敗)に照らすと「検出できていない」側。
- **復号までの差。** 回線計算(衛星 1.3 W・0 dBi、偏波損失 3 dB、ダイポール 2.15 dBi、NF 8 dB、12 kHz 帯)では、
  空が開けていれば 520 km で SNR 約 +16 dB、1,400 km で約 +7 dB のはず。推定した受信 SNR は −4〜−11 dB で、
  **13〜26 dB 足りない**。候補は、窓ガラスのコーティング、上階の床板・建物、室内の雑音、衛星の姿勢、
  1090 MHz 用の給電のままのダイポールの不整合(未切り分け)。
- **ADS-B への影響。** 窓による停止は 4 日で合計約 38 分(11/7 10.0、11/8 12.3、11/9 7.7、11/10 7.6 分)で、D3 の
  1 日 45 分以内。影響が大きかったのは停止より向きで、**水平(11/8 12:05〜11/11 19:30)の間、受信率は 08:00〜18:30 で
  7〜8%**(垂直の 11/3〜11/7 は 21〜28%)。この期間は基準線から除外する(`documents/antenna-placements.tsv`)。
- 11/8・11/9 の生の録音は削除済みで、改良した方法では解析し直せない。11/10 の生の録音(8 ビット IQ、2 本で約 226 MB)は
  RPi の `~/sat/iq/` に残してある。
- 詳しい報告書(SatNOGS・adsb.lol 由来の値を含むため、リポジトリ外)を、開発機の `~/kikicom-data/satellite/` で
  レビュー中。

## 未決・未検証

1. **視野マスクは仮定を含む。** 実際に指定された開口は南東(90〜200°)だけ。西〜北西は 45°、
   北東は 60° 以上で見えると仮定した。アンテナの置き場所が決まったら、実測で直す。
2. **アンテナ。** いまのロッドは 1090MHz 用の 7cm。437MHz には 約 17cm(1/4 波長)が要る。
   17cm は 1090MHz では約 0.6 波長で、ADS-B にもある程度使える見込み(要実測)。
   垂直のアンテナは真上に感度の穴があり、CubeSat の高仰角パスには不利。斜め 45° が折衷案(要試験)。
   アンテナを替えたら `documents/antenna-placements.tsv` に記録する(基準線がそこで不連続になる)。
3. **屋外化(検討中)。** 壁に最近空いたエアコン用の穴を使い、アンテナを屋外へ出す案。
   確認すること: 穴の向き(南東の開口か)、同軸を通す隙間と再シール、集合住宅の規約(ベランダは共用部の
   場合がある)、同軸の長さと損失、LNA の置き場所(アンテナ直下)。
4. **冬の強風・雪・氷への対策(検討中)。** 伸縮ロッドは強風で曲がる・折れる。着雪・着氷で同調がずれる。
   案: 17cm の短い素子を剛性のある棒(真鍮・ステンレス)で作る、塩ビ管のレドームで覆う(雪と風を避ける、
   端に水抜き穴)、軒下に固定する、同軸にドリップループとコネクタの防水処理、落下防止ワイヤー、
   嵐の日は取り込める着脱式の取り付け。静電気・雷対策(同軸の接地、避雷器)も要る。
5. **gr-satellites に IQ をどう渡すか。** `rtl_sdr` の出力は 8 ビットの IQ。形式の変換が要るかを試す。
   ドップラー補正は、録音後に skyfield の計算でずれを IQ に反映する案。
6. **Foresail-1p の CW ビーコン。** 2026-11-07 に SGICD(V2、2026-02-23、19 ページ。
   https://foresail.github.io/docs/FS1p_Space_Ground_Interface_Control_Sheet.pdf)を取得して読んだ。
   **SGICD に CW ビーコンの記述はない**(アアルト大学の案内ページの UHF の項に「CW beacon」とあるだけで、
   周期・形式は未公開)。SGICD にある仕様は次のとおり(リポジトリには PDF を入れない):
   - 437.125 MHz、ドップラー ±10 kHz、帯域 20 kHz、GMSK、シンボルレート 4800/9600(標準)/19200/38400、出力 1.3 W。
   - **円偏波**(旋回の向きは姿勢次第)。**任意の直線偏波で受けると 3 dB の減衰で、フェージングは最小**。
   - フレームは Skylink PHY(プリアンブル 0xAA×6、同期語 0x1ACFFC1D、Golay-24 の長さ欄、RS(255,223))。
   - **平均で 60 秒おきにマルチフレームのビーコン**を送る(OBC・EPS・ADCS・UHF のハウスキーピング、打ち上げ直後は
     Deployment も、VC3 にアマチュア中継のビーコン)。したがって、検出の狙いは Suomi-100 と同じ
     「約 60 秒おきの短いバースト」で、CW の検出には頼らない。
   - 受信側に有利な点: 衛星は「ダウンリンク専用のファイル転送モード」も持つ(第三者局で受けられるよう設計)。
7. P1 以降の `OnSuccess=`/`OnFailure=` による復帰と、見張り役のタイマーの実装。
